# Feedback

In-app feedback for Android + iOS under `common/feedback/`, group `studio.lunabee.feedback`. Tester, PO or client writes bug / idea / remark, optionally adds redacted screenshot or app files → item lands in Intake queue of Plane project; "My feedback" lists what this install sent, with live triage status. First consumer oneSafe 6 `devBeta` (separate oneSafe6 PR). Ticket LBA-3. Usage guide + bot setup: `common/feedback/README.md`. Module layout: [[architecture]].

## Modules

| Module | Published | Role |
|---|---|---|
| `feedback-core` | `studio.lunabee.feedback:feedback-core` | models, `LBFeedbackConfig`, `LBFeedbackTransport` contract, `LBFeedbackError`, `LBFeedbackStore`, `LBFeedbackClient` (headless API), metadata, `LBFeedbackScreenCapture` |
| `feedback-plane` | `studio.lunabee.feedback:feedback-plane` | `LBPlaneFeedbackTransport` + `LBPlaneDescriptionBuilder` |
| `feedback-ui` | `studio.lunabee.feedback:feedback-ui` | Compose Multiplatform screens, `LBFeedback` entry point, Android Activity + triggers, iOS `LBFeedbackController` |
| `feedback-test` | **no** (no publish conventions, no version) | shared test fakes for the three above |

- All `lunabee.kmp-android-library-conventions` → Android + iosArm64 + iosSimulatorArm64, **no JVM target** → BOM pins them with plain `addModule` (no `-jvm`).
- One version: `FEEDBACK_CORE_VERSION`; `FEEDBACK_PLANE_VERSION`, `FEEDBACK_UI_VERSION` alias it.
- Dependency direction: `feedback-plane` → `api(feedback-core)` + `api(ktor-client-core)`; `feedback-ui` → `api(feedback-core)`. `feedback-ui` never depends on `feedback-plane`: app picks transport. `feedback-core` knows neither Plane, Ktor nor Compose. No other Lunabee module used.
- No DI framework: `LBFeedback.install` builds `LBFeedbackGraph` by hand → no Koin/Hilt forced on consumers (oneSafe = Hilt).

## Core — headless API and seams

- **`LBFeedbackClient`** holds business rules once; built-in ViewModels delegate to it. App with own UI depends on `feedback-core` only, no Compose. Built from `(config, transport, store)` or `(transport, store, metadataProvider)`.
  - `send(draft)`: size check → create item → store it (status `Pending`) + remember reporter → upload attachments **one by one, stop at first failure** → `LBFeedbackSendResult.Sent` or `PartiallySent(item, remaining, error)`. Item kept once created.
  - `retryAttachments(remoteId, files)` uploads only given files to existing item.
  - `refreshStatuses()`: `transport.get` per item; failure → keeps last known status.
  - `update` / `delete` only while `Pending` (`canEdit`), else `LBFeedbackError.NotEditable`. Why: once PO accepts / declines / marks duplicate, tester must not overwrite triage edits. `delete` treats remote `NotFound` as done → removes locally.
  - `update` rebuilds remote description from **stored** item metadata + new text, never parses Plane HTML; attachments of draft ignored.
- **`LBFeedbackTransport`** = relay seam: `send` (create only) / `get` / `update` / `delete` / `attach` (one file, separate call so failed file retried alone). Future relay transport (public beta, no token in app) implements same interface; nothing else changes.
- **`LBFeedbackError`** sealed, **thrown** (like `LBParseException`): `Unauthorized`, `RateLimited`, `Network`, `TooLarge`, `Server(statusCode)`, `AttachmentRejected`, `NotEditable`, `NotFound`. `NotEditable` comes from client only, never transport. UI maps each to localized message.
- **`LBFeedbackStatus`** mirrors Plane intake codes: `Pending -2`, `Declined -1`, `Snoozed 0`, `Accepted 1`, `Duplicate 2`.
- **Metadata**: `LBFeedbackMetadataProvider` (`fun interface`), standard = `LBFeedbackDefaultMetadataProvider(config)`: app version name/code + build variant from `LBFeedbackConfig` (library can't read app `BuildConfig`), device, OS, locale, library version, UTC send time, plus `extras: suspend () -> Map` hook (never user data).
  - Library version = `FeedbackCoreVersion`, generated by `generateFeedbackVersion` task in `feedback-core/build.gradle.kts` from `AndroidConfig.FEEDBACK_CORE_VERSION` into `build/generated/feedbackVersion`, wired as `commonMain` srcDir → no hand-synced constant.
- **Store** = `LBFeedbackStore` (items flow newest first, reporter name, `add`, `update(remoteId, transform)`, `remove`, `setReporterName`).
  - `DataStoreFeedbackStore` (internal): Preferences DataStore, items as one JSON list (`lbFeedbackItems`) + `lbFeedbackReporterName`. `update` applies transform inside one `edit` → atomic, concurrent change to other field never lost. Unknown type / status code dropped on read.
  - Android `Context.lbFeedbackStore()` (process-wide `preferencesDataStore`); iOS `lbFeedbackStore()` singleton, file in **Application Support** dir (not Documents).
  - **Only disk write of the whole library.** Drafts, screenshots, files stay in memory.
- **`LBFeedbackScreenCapture`** (expect object, in core so own-UI apps capture without Compose) → JPEG `LBFeedbackAttachment` or `null`.
  - Android: `install(application)` tracks resumed activity (`ActivityLifecycleCallbacks`, `WeakReference`). `snapshot()` = `decorView.drawToBitmap()` on main thread; `encode` off main, downscale until ≤ 4.5 MB. Activities implementing `LBFeedbackCaptureExcluded` (the feedback Activity) never tracked; `isExcludedActivityResumed` lets shake trigger skip while form open.
  - iOS: key window `drawViewHierarchyInRect` → JPEG; `null` when no key window or over 5 MB.

## Plane intake — `feedback-plane`

`LBPlaneFeedbackTransport(baseUrl, workspaceSlug, projectId, token: suspend () -> String, httpClient)`. `X-API-Key` read per request. App owns `HttpClient` + engine (never closed here). **No automatic retries on POST** → would duplicate items.

| Call | Request |
|---|---|
| `send` | `POST …/projects/{id}/intake-issues/` `{"issue": {name, description_html, priority: "none"}}` |
| `get` / `update` / `delete` | `GET` / `PATCH` / `DELETE …/intake-issues/{workItemId}/` |
| `attach` 1 | `POST …/work-items/{workItemId}/attachments/` `{name, type, size}` → `upload_data {url, fields}` + `asset_id` |
| `attach` 2 | multipart `POST` file to presigned `upload_data.url` with `fields`, **without** API key |
| `attach` 3 | `PATCH …/work-items/{workItemId}/attachments/{asset_id}/` `{"is_uploaded": true}` |

- **Id trap**: create response = intake **row**; its `issue` field = **work item** id. Remote id = work item id, used for both `intake-issues/{id}` and `work-items/{id}/attachments/`. Intake row id never kept. Verified in Plane CE v1.5.0 source.
- Title = `[Bug] / [Idea] / [Other] <title>` (no type field on create, no labels on create). PO sets priority.
- `LBPlaneDescriptionBuilder`: body (lines → `<br>`), reporter line, metadata table + extras — **every value HTML-escaped**.
- Errors: 401/403 `Unauthorized`, 404 `NotFound`, 413 `TooLarge`, 429 `RateLimited`, other non-2xx `Server(code)`, `kotlinx.io.IOException` `Network`; 400 on attach step 1 → `AttachmentRejected`; unknown status int on `get` → `Server`.
- MIME allow-list = Plane `ATTACHMENT_MIME_TYPES` setting (v1.5.0 list in transport KDoc + README): images, pdf, Office/OpenDocument, text/plain|markdown|csv, json, xml, audio, video, archives, octet-stream… Other type → `AttachmentRejected`. Logs → `text/plain`.
- Limits: 5 MB per upload (`LBFeedbackAttachment.MaxBytes`, checked before any call by client + transport); ~60 requests/min per key → 429. One attachment = 3 requests.
- Bot: dedicated Plane user, **Guest** of target project only, `guest_view_all_features` off, Intake on, long-lived token outside VCS. Guest may edit name + description of own items, delete them, upload attachments. One shared token → server can't tell testers apart → "My feedback" filtered locally from store.
- Unverified at delivery: presigned URL reachable from device (self-hosted → must point to public host), exact `upload_data` shape, Guest read of own intake items with `guest_view_all_features` off.

## UI — `feedback-ui`

- Compose Multiplatform (like `monitoring-ui`), EN + FR compose resources (`publicResClass = false`). Screens inherit app `MaterialTheme`; library-hosted screens wrap in `themeWrapper` from `install`, default `LBFeedbackTheme` (M3 light / dark scheme from `isSystemInDarkTheme()`), so hosted screens follow system dark mode unless app passes own theme.
- `LBFeedback` object: `install(config, transport, store[, themeWrapper])` — two overloads instead of default arg (Swift can't see defaults). `client` exposes headless API.
- Pending draft data in memory only (`LBFeedbackPending`): screenshot slot + app files. `setScreenshot` is `suspend` (decode / encode off main), `addAttachment` replaces same-name file, `removeAttachment`, `clearAttachments`. Cleared after send. Screenshot named `screenshot-yyyyMMdd-HHmmss.jpg` (UTC, capture / pick time) by `LBFeedbackAttachment.screenshotName()` in core — one builder for Android capture, iOS capture, gallery pick; redaction keeps name.
- Public composables `LBFeedbackFormScreen`, `LBFeedbackListScreen`, `LBFeedbackRedactScreen` → embed in app NavHost; ViewModels internal; `LBFeedbackTestTags`.
- **Host** (`LBFeedbackHost`, used by Activity + iOS controller): own small back stack, no navigation library. `LBFeedbackHostViewModel` holds stack of entries; route = sealed `LBFeedbackRoute` (`Form`, `Redact`, `List`, `Edit(remoteId)`). Each entry = own `ViewModelStoreOwner`, provided via `LocalViewModelStoreOwner`, store cleared on pop / host clear → each visit gets fresh ViewModels (two edits never share state).
- Form: failure → no queue, draft (files included) kept in memory, user taps Retry; partial send → "Retry attachments" for failed files only. Screenshot switch **off by default**, preview, redact. Redact = opaque boxes as 0..1 fractions, flattened into bitmap, re-encoded JPEG < 4.5 MB, common Compose.
- List: refreshes statuses on open; edit / delete enabled only while `Pending`.

### Android

- `LBFeedback.install(application, …)` = `install` + `LBFeedbackScreenCapture.install`.
- `LBFeedback.open(context, startOnList)`: draw resumed activity on main thread, encode async (form shows it when ready), start `LBFeedbackActivity` (`NEW_TASK` when context not an Activity). No tracked activity / failed draw → opens without screenshot.
- `LBFeedbackActivity`: library manifest, not exported, `adjustResize`, `enableEdgeToEdge()` (bar icons follow system mode), `Theme.LBFeedback` (platform theme, `values-night` window background = M3 baseline background, no white flash before Compose), `FLAG_SECURE` set before `setContent`, `LBFeedbackCaptureExcluded`. Form column `consumeWindowInsets(padding).imePadding()` — nav-bar inset not counted twice above keyboard.
- **FLAG_SECURE rationale**: `drawToBitmap` draws app's own views → capture **works on FLAG_SECURE screens** (demo `FlagSecureActivity` proves it). So form may display secure content → form window itself secure (hidden in recents, not screen-capturable). Capture misses `SurfaceView`, video, separate windows (dialogs, popups).
- Opt-in triggers, both off unless app calls them:
  - `LBFeedbackNotification.show/hide`: ongoing notification, own channel, IMMUTABLE PendingIntent with capture extra → Activity captures in first `onCreate`. App must hold `POST_NOTIFICATIONS` on API 33+; library never asks, shows nothing otherwise. Tap while app backgrounded → tracked activity stopped, capture may be blank / skipped.
  - `LBFeedbackShakeTrigger.enable/disable`: accelerometer, foreground only (`ProcessLifecycleOwner`), 2.7 g, 1 s debounce, ignored while form resumed. Never in app that already uses shake (oneSafe shake-to-lock).
- Gallery: `PickVisualMedia` → no permission.

### iOS

- `LBFeedbackController` object (Swift-friendly, like `monitoring-ui`): `get(startOnList, onClose)` → `ComposeUIViewController` with `modalInPresentation = true` → swipe-down can't cut off a send; app dismisses in `onClose`. `captureScreenAsPending()` puts key-window capture in pending slot.
- v1: no gallery picker, shake, notification; no back gesture (top-bar Back only).

## Security invariants

- Token ships inside app → dev / beta builds only, never store build. Leak → rotate by hand in Plane. 401 still shows clear error.
- Nothing written to disk except store (sent items + reporter name). Screenshot + files memory only.
- Screenshot off by default, previewed, redactable.
- `LBFeedbackConfig.extras` and app-attached files reach Plane as is → **never user data**. Library has no log API, attaches no logs itself.
- All user text escaped in `description_html`.
- Feedback window `FLAG_SECURE` + never captured itself.
- API key never sent to presigned storage URL.
